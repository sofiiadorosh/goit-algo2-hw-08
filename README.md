# goit-algo2-hw-08

Домашнє завдання: LRU-кеш і Rate Limiter на основі Sliding Window.

Потрібен лише Python 3.8+ — сторонніх залежностей немає.

## Завдання 1. Оптимізація доступу до даних за допомогою LRU-кешу

Файл: [`lru_cache_range_queries.py`](lru_cache_range_queries.py)

Обробка `Q = 50 000` запитів до масиву з `N = 100 000` чисел:

- `Range(L, R)` — сума `array[L : R + 1]`;
- `Update(index, value)` — `array[index] ← value`.

Реалізовані функції:

| Функція | Опис |
|---|---|
| `range_sum_no_cache` | сума діапазону без кешування |
| `update_no_cache` | оновлення елемента без кешування |
| `range_sum_with_cache` | шукає `(L, R)` у `LRUCache` (K = 1000); при cache-miss (`-1`) рахує суму та зберігає через `put()` |
| `update_with_cache` | оновлює масив і лінійним проходом по ключах видаляє з кешу всі діапазони, що містять `index` |

Запити генеруються функцією `make_queries` (30 «гарячих» діапазонів, 95 % Range-запитів — гарячі, ~3 % — Update).
Обидва прогони виконуються на копіях одного масиву, а результати Range-запитів порівнюються між собою, тож кеш перевірено на коректність.

```bash
python3 lru_cache_range_queries.py
```

Приклад виведення:

```
Масив: 100,000 елементів | Запитів: 50,000 (Range: 48,473, Update: 1,527)

Без кешу :   5.50 c
LRU-кеш  :   1.93 c  (прискорення ×2.8)
```

**Висновок:** оскільки більшість запитів повторює невеликий набір гарячих діапазонів, більшість із них обслуговується з кешу за O(1) замість O(R − L). Попри інвалідацію після кожного Update, LRU-кеш пришвидшує обробку приблизно в 2.5–3 рази.

## Завдання 2. Rate Limiter з алгоритмом Sliding Window

Файл: [`sliding_window_rate_limiter.py`](sliding_window_rate_limiter.py)

Клас `SlidingWindowRateLimiter` (за замовчуванням `window_size = 10` с, `max_requests = 1`) зберігає мітки часу повідомлень кожного користувача в `collections.deque`.

| Метод | Опис |
|---|---|
| `_cleanup_window` | видаляє повідомлення, старші за вікно; якщо вікно порожнє — видаляє запис про користувача |
| `can_send_message` | `True`, якщо у поточному вікні ще не досягнуто ліміту (перше повідомлення — завжди `True`) |
| `record_message` | записує повідомлення, якщо воно дозволене; інакше повертає `False` |
| `time_until_next_allowed` | час у секундах до моменту, коли можна надіслати наступне повідомлення |

```bash
python3 sliding_window_rate_limiter.py
```

Приклад виведення:

